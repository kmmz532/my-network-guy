# 開発の手順

Node.js 22 と npm を利用する。Windows では、vite のビルドと撮影を大文字のドライブ名のパス（`F:\…`）から実行する。

```bash
npm ci            # 依存パッケージのインストール
npm run dev       # 開発サーバーの起動
npm run verify    # 型・ESLint・全試験・JSON・言語ファイル・仕様との突き合わせ
npx vitest run <ファイル> --reporter=dot   # 作業中に、変更した箇所の試験だけを実行する
node scripts/shoot.mjs <場面>             # 画面を shots/ に撮影する（場面の一覧は tools.md）
```

JSON と言語ファイルは、エディタで直接書き換えず、`scripts/json.mjs` と `scripts/lang.mjs` で編集する（[AGENTS.md](../AGENTS.md)）。セーブの形を変えるときは [セーブデータ](save.md) の手順に従う。

## 完了の条件

変更は `npm run verify` に合格した時点で完了とする。画面に関わる変更は `node scripts/shoot.mjs <場面>` で撮影して確認し、見た目が変わる場合は前後の画像を示して了承を得る。

## 原則

遊んだときの挙動、画面、ターミナルの出力、既存のセーブの読み込みは、意図した変更以外では変えない。内部の構成を変えるときは、挙動の記録の試験（`src/__golden__`）との一致で確かめ、途中で見つけた不具合は別の `fix:` のコミットで直す。決まりは注意ではなく、ESLint の規則・試験・検査で守らせる。

設計にない判断に迷ったときは、同じ種類の箇所の既存の決定に合わせる。型や登録表に項目が足りなければ、`src/data/schema.ts` にある項目をそのまま追加する。データが意図を示しているのにコードが読んでいなければ、データに合わせて別の `fix:` のコミットで直す。どれにも当たらなければ今の挙動を保つ方を選び、外部仕様が変わる判断だけは、止めて利用者に確認する。

想定外の入力は既定値で埋めず、例外で止める。セーブの移行だけは、古いセーブを読めることを優先する。

## 試験

試験は、シミュレーションの結果・依頼の合否・セーブの移行のように、壊れうる振る舞いを守るものだけを追加する。CSS やソースの文字列の照合、型で保証される事、props の素通しを確かめる試験は作らない。既存の試験を洗い出して削除する作業も行わない。

## コミット

作業を終えるごとに、`git add` でファイルを指定してコミットする。`git stash` と `--no-verify` は利用しない。ソースとコミットメッセージには、作業の番号や非公開の文書への参照を書かない。
