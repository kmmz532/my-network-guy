## RIP・OSPF・BGPを試す

動的ルーティングは、タイトル画面の「サンドボックス」で試します。案件では機器や設定が固定されていて、自由に構成できないことがあるためです。

### 共通の準備

1. サンドボックスを開始する。
2. ルーターを2台置き、ルーター同士をLANケーブルでつなぐ。
3. ルーターの間のネットワークを `10.0.12.0/30` として設計する。
   - ルーターAの接続口: `10.0.12.1 / 30`
   - ルーターBの接続口: `10.0.12.2 / 30`
4. ルーターA側にPCを置き、PCを `192.168.1.10/24`、ゲートウェイを `192.168.1.1` にする。
5. ルーターB側にPCを置き、PCを `192.168.2.10/24`、ゲートウェイを `192.168.2.1` にする。
6. ルーターAの別の口を `192.168.1.1/24`、ルーターBの別の口を `192.168.2.1/24` にする。

口の番号は、機器の画面の背面で確認します。以下の例では、`0` がPC側、`1` がルーター間の口です。実際の配線に合わせて読み替えてください。

プレフィックス長は `/0`〜`/32` から選べます。ルーター間の口は、2台だけをつなぐ `/30` を例にします。`/31` でも同じ手順で設定できます。

`10.0.12.0` はネットワークアドレスのため、口には設定しません。設定画面で「詳しく」を開くと、ネットワークとプレフィックス長を指定できます。ルーター間の口では、ネットワーク欄に `10.0.12.0` を入力し、プレフィックスを `/30` に選んでから、IPアドレスとして `10.0.12.1` または `10.0.12.2` を入力します。プレフィックスが `/24` のままの口にIPアドレスを入力すると、そのIPアドレスからネットワークが自動で決まります。

ターミナルでは、次のように入力します。

```text
ip address 1 10.0.12.1 255.255.255.252
```

もう一方のルーターには、実際の配線に合わせた口の番号で、次を入力します。

```text
ip address 1 10.0.12.2 255.255.255.252
```

`10.0.12.0` は、RIP・OSPF・BGP に「このネットワークを使う」と伝えるときに使います。口に設定するIPアドレスと、ルーティングで指定するネットワークは別の値です。

### RIPを試す

RIPは、隣り合うルーターから経路を受け取る、最も簡単な動的ルーティングです。

ルーターAのターミナルで入力します。

```text
router rip
network 192.168.1.0
network 10.0.12.0
```

`router rip` は、そのルーターで RIP を有効にします。続く `network` は、IPアドレスを設定する命令ではありません。指定したネットワークに属する口を RIP に参加させ、そのネットワークを隣のルーターへ知らせます。設定画面では、口ごとの「RIP に参加」でも同じ設定ができます。

この例では、`192.168.1.0` がPC側のLAN、`10.0.12.0` がルーター間のリンクです。口のIPアドレスは、先に `192.168.1.1` や `10.0.12.1` のように設定しておきます。`network` には、IPアドレスそのものではなく、ネットワークアドレスを指定します。

ルーターBでは、LAN側のネットワークを替えます。

```text
router rip
network 192.168.2.0
network 10.0.12.0
```

2台のPCから相手のPCへ `ping` を実行し、通信できれば成功です。ルーターAまたはルーターBのターミナルで `show ip route` を実行すると、相手側のネットワークが `R` の経路として表示されます。`show ip rip database` では、RIP で覚えた経路だけを確認できます。PCで `show ip route` を実行すると、自分の直結の経路 `C` と、既定の経路 `S*` だけが表示されます。

ターミナルで `ping` または `traceroute` を実行すると、パケットがマップ上で経路に沿って動きます。通過するルーターの順番と、失敗したときに止まる場所を観察できます。

#### 4台のルーターでRIPを試す

ルーターを4台置き、PCとルーターを一直線につなぎます。

```text
PC-A -- R1 -- R2 -- R3 -- R4 -- PC-B
```

各ルーターは2つの口を使います。`/30` のリンクでは、ネットワークアドレス（`.0`）とブロードキャストアドレス（`.3`）を口に設定できません。使えるのは `.1` と `.2` の2つです。このため、ルーター間のリンクごとに別の `/30` を用意します。

| 接続 | ネットワーク | 左側の機器 | 右側の機器 |
| --- | --- | --- | --- |
| PC-A - R1 | `192.168.1.0/24` | PC-A `192.168.1.10` | R1 `192.168.1.1` |
| R1 - R2 | `10.0.12.0/30` | R1 `10.0.12.1` | R2 `10.0.12.2` |
| R2 - R3 | `10.0.23.0/30` | R2 `10.0.23.1` | R3 `10.0.23.2` |
| R3 - R4 | `10.0.34.0/30` | R3 `10.0.34.1` | R4 `10.0.34.2` |
| R4 - PC-B | `192.168.2.0/24` | R4 `192.168.2.1` | PC-B `192.168.2.10` |

PC-Aのゲートウェイは `192.168.1.1`、PC-Bのゲートウェイは `192.168.2.1` にします。口の番号は、実際の配線に合わせて読み替えてください。

各ルーターのターミナルで、次を入力します。

R1:

```text
ip address 0 192.168.1.1 255.255.255.0
ip address 1 10.0.12.1 255.255.255.252
router rip
network 192.168.1.0
network 10.0.12.0
```

R2:

```text
ip address 0 10.0.12.2 255.255.255.252
ip address 1 10.0.23.1 255.255.255.252
router rip
network 10.0.12.0
network 10.0.23.0
```

R3:

```text
ip address 0 10.0.23.2 255.255.255.252
ip address 1 10.0.34.1 255.255.255.252
router rip
network 10.0.23.0
network 10.0.34.0
```

R4:

```text
ip address 0 10.0.34.2 255.255.255.252
ip address 1 192.168.2.1 255.255.255.0
router rip
network 10.0.34.0
network 192.168.2.0
```

PC-Aのターミナルから `ping 192.168.2.10` を実行します。R1・R2・R3で `show ip route` を実行すると、遠いネットワークほど、多くのルーターを経由して学んだ `R` の経路として表示されます。`traceroute 192.168.2.10` では、R1からR4までの通過順を確認できます。RIP は、経由するルーターが16台以上になる宛先へは届きません。

### OSPFを試す

OSPFは、RIPより大きなネットワークに向く動的ルーティングです。この手順では、すべての口をエリア `0` に入れます。

ルーターAのターミナルで入力します。

```text
router ospf
network 192.168.1.0 0.0.0.255 area 0
network 10.0.12.0 0.0.0.3 area 0
```

ルーターBでは、LAN側のネットワークを替えます。

```text
router ospf
network 192.168.2.0 0.0.0.255 area 0
network 10.0.12.0 0.0.0.3 area 0
```

設定画面では、口ごとの「OSPF に参加」と、エリア・コスト・優先度・Hello 間隔・デッド間隔の欄でも同じ設定ができます。

PC間の `ping` が通り、`show ip ospf neighbor` で相手のルーターが隣接として表示されれば成功です。隣接しないときは、`show ip ospf neighbor` に、相手のルーターと理由（エリア・Hello 間隔・デッド間隔の違い）が表示されます。ルーター間のIPアドレスとサブネットも、両端で一致させます。

エリアを分けるときは、エリア `0` に接していないエリアの経路が届かないため、すべてのエリアをエリア `0` の境界のルーターにつなぎます。

### BGPを試す

BGPは、異なるAS（ネットワーク組織）どうしで経路を交換するためのプロトコルです。BGPに対応する機器は、エッジルーターです。エッジルーターを2台置き、ルーターAをAS `65001`、ルーターBをAS `65002` とします。

ルーターAのターミナルで入力します。

```text
router bgp 65001
neighbor 10.0.12.2 remote-as 65002
network 192.168.1.0 mask 255.255.255.0
```

ルーターBでは、自分のAS、相手のIPアドレスとAS、広告するLANを入れ替えます。

```text
router bgp 65002
neighbor 10.0.12.1 remote-as 65001
network 192.168.2.0 mask 255.255.255.0
```

BGPでは、次の3つが両端でそろっている必要があります。

- `neighbor` に指定する相手のIPアドレス
- `remote-as` に指定する相手のAS番号
- 相手側の `router bgp` に設定した自分のAS番号

相手は両方のルーターが `neighbor` に設定して、はじめて隣接になります。`show ip bgp summary` で、相手の状態が `Established` になれば成功です。`Idle` のときは、理由（AS番号の不一致、相手の設定がない、相手のアドレスに届かない）が表示されます。PC間の `ping` が失敗して理由が `bgp.no_session` の場合は、neighborのIPアドレスまたはAS番号が一致していません。BGPはOSPFと違い、相手を明示して設定します。

### うまくいかないときの確認

| 症状 | 確認すること |
| --- | --- |
| `ip.unset` | ルーターとPCの各口にIPアドレスを設定したか |
| `iface.none` | `network` のネットワークが、実際の口のIPアドレスと同じサブネットか |
| `ospf.no_neighbor` | ルーター間の配線、IPアドレス、サブネット、エリア、Hello 間隔、デッド間隔が一致しているか |
| `bgp.no_session` | neighborのIPアドレスとremote-asが、相手の設定と一致しているか |
| `rip.unreachable` | 宛先までのルーターが16台未満か |
| `route.none` | 宛先のネットワークを `network` で広告したか |
| 経路がない | `show ip route` と `traceroute` で、どこまで届いているか |

`show running-config` は、現在の設定をまとめて表示します。設定を変えたあとは、もう一度 `T` でテストを実行します。
