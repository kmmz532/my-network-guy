# アーキテクチャ

## 層の分け方

ゲームのルールと描画を分けて作っています。

| 層 | 場所 | 備考 |
| --- | --- | --- |
| ルール | `src/sim/` | 資金、時間、社員、施工、評価を計算する。純粋関数で書き、テストをそろえる |
| ネットワーク | `src/network/` | 配線、IP アドレス、疎通の判定、ケーブルの長さ |
| 案件 | `src/contracts/` | 依頼の生成、達成条件の判定 |
| 状態 | `src/stores/` | Zustand のストア。ゲームの状態をまとめ、ルールの関数を呼ぶ |
| 画面（HUD・ダイアログ） | `src/components/` | React。ツールバー、機器の画面、ショップ、インベントリなど |
| 画面（マップ） | `src/game/` | Pixi.js。マップ、社員、ケーブル、パケットの描画 |

ルールの層は React や Pixi.js を読み込みません。そのため、画面を動かさずにテストできます。

## 状態の流れ

1. 利用者の操作は `src/input/`（キー）か `src/components/`（ボタンや押す操作）から、ストアの操作を呼ぶ。
2. ストアは `src/sim/` などの関数で新しい状態を計算し、結果を保存する。
3. 画面（React と Pixi.js）はストアの状態を読んで描く。

時間は一定の間隔で進みます。描画は画面の更新ごとに行い、ルールの計算は時間の進みに合わせて行います。

## 設計の方針

Web ページとしてではなく、ゲームとして設計します。ゲームの本体は React に依存させず、React は場面の上に重ねる表示の層とします。

- ゲームの本体は、状態、時間の進行、ルール、入力の解釈、セーブです。
- 場面（タイトル、ゲーム）を単位とし、場面の切り替えは `App` だけが持ちます。`App` は起動、エラー、場面の切り替えだけを行います。
- ゲームの状態は1つのストアが持ちます。更新は毎ティックの順序の決まった処理で行います。
- 入力（キー、ポインタ）は、ゲームへの命令に変換して渡します。部品が状態を直接書き換えません。
- 置き場所は、ページの部品が何を持つかではなく、ゲームの何をどの層が持つかで決めます。

## 置き場所の規則

| 置く物 | 置き場所 |
| --- | --- |
| 画面に出さない処理（セーブ、時間を進めるループ、描画のループなど） | React の外のモジュール（`src/services/`、`src/sim/`） |
| 画面に出す値（開いている画面、枠、保存の印など） | ストア。部品は `use` で読む |
| 押したときだけ使う関数 | ストアの `getState()` で呼ぶ |
| 場面だけが使う状態 | その場面の部品 |
| 開いている画面の状態 | ストア。スマホかパソコンかは、表示のときだけ分ける |
| 時刻と設定 | ルールの関数の引数で渡す。ルールの中で `Date.now()` や `loadSettings()` を読まない |

新しく書くコードと、手を入れたコードは、この規則に合わせます。

## キー入力の受け口

`window` への `keydown` の登録は `src/input/keyRouter.ts` の1か所だけです。キーは次の順に受け、先に処理したものが次へ渡しません。

1. 横取り（`captureKeys`）: ドラッグ中、一覧を開いている間など、一時的にキーを奪う処理。あとから登録したものが先に受けます。DOM の要素より先に受け、受けたキーは要素に渡しません。
2. 場面の層（`addKeyLayer`）: 場面が持つキー（タイトルの Enter・矢印、マップの R など）。
3. キーの表（`KEYMAP`）: ゲームの場面だけです。ポップアップ、ウィンドウ、道具の順は `keymap.ts` の Esc の処理が持ちます。

部品は、`window` に直接 `keydown` を登録せず、1 か 2 に登録します。

## ディレクトリ

| パス | 備考 |
| --- | --- |
| `src/sim/` | ルール |
| `src/network/` | ネットワークの計算 |
| `src/contracts/` | 案件 |
| `src/stores/` | ストア。`useGameStore.ts` が基本の状態と毎ティックの処理を持ち、操作は種類ごとの `slices/`（ウィンドウ・設計・社員・オフィス・案件・時間と資金・画面・デバッグ・セッション）に置く。状態から値を引く関数は `gameHelpers.ts`、操作の結果の反映と設計の履歴は `gameOps.ts`、毎ティックの処理は順序の決まった系として `tickSystems.ts` |
| `src/components/` | React の画面 |
| `src/game/` | Pixi.js の描画と、マップへの入力。`Scene.ts` が描画を持ち、カメラ（`MapCamera`）、位置の判定（`MapHit`）、ポインタ入力（`MapInput`）、マップ上の説明（`MapTip`）、社員の動き（`OfficeStaffMotion`）に分ける |
| `src/input/` | キー入力の受け口（`keyRouter.ts`）とキー操作の割り当て（`keymap.ts`） |
| `src/services/` | セーブ（IndexedDB、JSON ファイル）と移行、時間を進めるループ（`tickLoop.ts`） |
| `src/settings/` | 端末ごとの設定（UI の大きさ、時間の速さなど） |
| `src/ui/` | ウィンドウ、ポップアップ、スマホ向けの表示 |
| `src/i18n/` | 翻訳キーと `t()` 関数 |
| `src/data/` | ゲームデータのスキーマ（zod） |
| `src/assets/` | 言語ファイル、ゲームデータ（JSON）、スプライト |
| `src/generated/` | ビルド時に生成する型。Git の管理対象外 |
| `plugins/` | Vite のプラグイン（ゲームデータの検証と型生成） |
| `scripts/` | 開発用のツール |

## 新しく機能を足すとき

ルールは `src/sim/` などに純粋関数として書き、テストを足します。文言は言語ファイルに置き、数値はゲームデータ（JSON）に置きます。セーブの形式を変えたときは、セーブの移行を足します（[セーブデータ](save.md)）。
